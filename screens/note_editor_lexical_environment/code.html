01 How V8 Allocates Contexts for Inner Functions

In JavaScript engines like Google V8, when an outer function completes execution, its local activation record is typically popped off the call stack. However, whenever any nested function closes over an identifier from that scope, V8 promotes the entire scope to a Shared context object on the V8 heap. This retains not just the explicitly accessed primitive variables, but under certain multi-closure constellations, causes unexpected reference pin-down.

warning
Scope Pollution & Memory Pinning Pitfall

Warning: If an unused variable in the closure scope references large buffers (such as raw IPC packets or file streams), it may prevent garbage collection entirely if any sibling closure escapes to an external callback or long-lived event listener.
